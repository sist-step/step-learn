# STEP Learn

Moodle の「よく使う機能だけ」を、速く・安く・使いやすく作り直した軽量 LMS です。
Node.js（Hono）＋ SQLite で動き、教材ファイルはサーバーのローカルディスク（`data/files`）に保存します。
1 台の小さな VPS で十分に動く構成です。

## 機能（現時点）

- **認証**：メール＋パスワードでの登録とログイン、セッション管理、プロフィールとパスワードの変更
  - 新規登録はメールアドレスの確認が必要です（届いたリンクから氏名・ユーザー名・パスワードを設定）
  - ログインはメールアドレスとユーザー名のどちらでもできます。ユーザー名の導入前に登録したユーザーは、アカウント画面で設定します
  - パスワードを忘れた場合は、ログイン画面からメールのリンク（有効期限 1 時間）で設定し直せます。設定するとすべての端末でログアウトされます
  - `MICROSOFT_CLIENT_ID` を設定すると、ログイン画面と新規登録画面から Microsoft アカウント（組織のアカウントと個人のアカウント）でもログインできます（通常モードだけ。下の「Microsoft アカウントでのログイン」）
    - 同じメールアドレスのアカウントがあれば、そのアカウントに連携してログインします。なければ氏名とユーザー名を入力して登録します（パスワードは設定せず、あとからアカウント画面で設定できます）
    - Microsoft がドメインの持ち主を確かめていないメールアドレス（組織の管理者が自由に設定できるもの）は、ほかの人のアカウントの乗っ取りに使えるため、照合にも登録にも使いません。その場合は、メールアドレスで登録してからアカウント画面で連携します
    - アカウント画面で、ログイン中のアカウントに Microsoft アカウントを連携・解除できます。連携できるのは 1 人 1 つまでで、パスワードを設定していないアカウントは解除できません
  - 管理者は CLI（`npm run user:create`）で作成します。Web からの登録はすべて学生になります
  - Moodle のコースバックアップから、コース・参加者を CLI（`npm run moodle:import`）で取り込めます
  - ロールは 管理者 / 教師 / 学生。コースを作成できるのは管理者だけです
- **コース**
  - コース一覧と検索（参加しているコースのみ。管理者は登録していないコースも表示できる）。「進行中」と「すべて」の切り替え（開始日・終了日で判定。端末ごとに記憶。「すべて」では終了したコースも出し、開始前のコースは教師として登録している人と管理者にだけ出す。ダッシュボードとサイドバーは進行中のコースだけ）、ダッシュボード（受講中・担当コース、進捗、「続きから学習」）
  - 作成（管理者がコース一覧や管理画面のモーダルから）・編集・削除、開始日と終了日、カラー、コースアイコンとヒーロー画像（PNG / JPEG / WebP / GIF、最大 5MB。アイコンは未設定なら頭文字を表示）
  - 学生の自己登録はなく、管理者か教師が参加者として追加したコースだけが見える
  - セクションとアイテム（ページ＝Markdown / リンク / ファイル / 画面共有 / コーディング問題 / 小テスト / ファイル自動配布 / コーディングエージェント）
  - 編集モードでの追加・並べ替え・削除（オンにするとブラウザを閉じるかログアウトするまで、どのコースでも続く）。オフのときは教師にも学生と同じ見え方で表示する
  - セクション・アイテムごとの「学生に非表示」（学生には一覧にも出さず、URL を開いても 404。進捗の計算からも外す）
  - セクション・アイテムごとのアクセス制限（編集モードの「…」>「アクセス制限」）。Moodle の「アクセス制限」と同じ条件を組み合わせられる
    - 条件: 日付（〜以降・〜より前）、アイテムの完了（完了している・完了していない・合格している・不合格になっている。「直前のアイテム」も選べる）、評点（コーディング問題でクリアした制約の割合の最高値、小テストのアイテムで正解した割合の最高値が ○% 以上・○% 未満）、ユーザープロフィール（氏名・ユーザー名・メールアドレスが「一致する・含む・含まない・で始まる・で終わる・空である・空でない」）、制限セット（条件の入れ子）
    - 組み合わせ: セットごとに「すべて満たす・いずれかを満たす・どれも満たさない・すべては満たさない」。合格はコーディング問題を一度でもクリアしたこと・小テストのアイテムに一度でも合格したこと、不合格は判定済みの提出（小テストは受験）があってまだクリア（合格）していないこと
    - 条件を満たしていない学生への見せ方は、目のアイコンで選ぶ（条件を見せる／一覧にも出さない）。「すべて満たす」「どれも満たさない」では条件ごとに、それ以外では制限全体で 1 つ
    - 条件を見せるときは、一覧に鍵と満たしていない条件だけを出し、開けない（URL を開いても 404。完了の切り替え・ファイル・コーディング問題・画面共有・ファイル自動配布も同じ）。開けないセクションは、名前と条件だけを出して中のアイテムを出さない。前後のアイテムへの移動と「続きから」は開けないアイテムを飛ばす。教師はいつでも開け、一覧にすべての条件の説明が出る
    - 進捗は制限に関係なく数える。制限は Moodle の availability と同じ形の JSON で `sections.availability` / `items.availability` に置く（`lib/restriction.ts`）
  - 学生ごとの完了チェックと進捗表示、前後ナビと目次付きの閲覧画面
  - 参加者管理（メールで追加、ロール変更、除外）
  - コーディング問題：セクションに「コーディング問題」アイテムを追加すると、学生がブラウザのエディターでコードを書いて提出できる。言語は Web（HTML / CSS / JavaScript。書きながら隣にプレビューとコンソールを表示）。Python（sandbox のコンテナで実行して結果を表示。下の「コードを実行する sandbox」）の処理もあるが、今は新しいアイテムでは選べない（`src/lib/sandbox.ts` の `SELECTABLE_CODE_LANGUAGES` に足すと選べる。作ってあった Python のアイテムはそのまま動く）。書きかけのコードは自動で保存され、提出は出し直せる（前の提出も残る）。教師は追加したあとの編集画面で、問題文・最初に入れておくコード・採点基準・満点を設定する
    - 採点：`OPENROUTER_API_KEY` を設定していると、提出のたびに AI が採点基準に沿って点数と講評を付ける（Python は、提出されたコードを sandbox で実行した結果も AI に渡す）。採点は順番に行い、終わると学生の画面に結果が出る。AI が採点するときは、続けて提出できるのは 1 分に 1 回まで。設定していなければ自動では採点しない
    - 教師はアイテムの「提出」から、学生ごとの提出（コード・プレビュー・実行結果・AI の採点・提出の履歴）を見て、点数とコメントを付けられる。教師が付けた点数は AI の点数より優先して成績になる。AI の採点はやり直せる
    - 編集画面の AI：「下書きを作る」は問題文から最初のコードと制約の下書きを、制約の欄の「AI で作る」は問題文と最初のコードから制約だけを作る（どちらも保存前の値を使い、入れた内容は教師が確かめて保存する。Moodle モードは「AI で作る」だけ）。AI アシスタントを使える人には「AI と相談する」も出し、押すとパネルでこのアイテムを選んだ新しいチャットが始まる（開いていたチャットは閉じる）。選んだアイテムはチャットに残り、パネルの入力欄の上に出る。AI は今の問題文と制約を読み、両方あれば改善案を、どちらかがなければ埋める案を確認カードで出し、作るのに必要なことが分からなければ先に質問する
  - AI アシスタント：教師（`AI_EMAIL_DOMAIN` のメールアドレスで、管理者・全体ロールが教師・いずれかのコースの教師のどれか）は、ヘッダー右上の ✦ から右側のパネルを開き、AI に頼める。AI は管理しているコースの内容を読み、教材を作ったり直したりする。受講者・成績・提出は扱わない
    - セクションとアイテム（ページ・リンク・ファイル・コーディング問題）の追加と並べ替えはすぐに実行する。追加したものは学生に非表示で作る
    - ファイルが要るとき（ファイルのアイテムの追加・ファイルの差し替え）は、AI が会話にファイルを選ぶカードを出し、受け取れる種類（PDF だけ、画像だけなど）も AI が用途に合わせて決める。受け取ったファイルはアイテムに使うまでサーバーに置き（Moodle モードは利用者の下書き領域）、使わないまま期限（通常モード 5 日・Moodle モード 3 日）を過ぎたら消す。AI はファイルの中身を読まない
    - 今ある内容の変更（セクション・アイテムのタイトルや本文、コーディング問題の制約など）と、学生への表示・非表示の切り替えは、変更前と変更後（本文は差分）を並べた確認カードを出し、「実行する」を押してから実行する。カードを出したあとに同じものが変えられていたら、上書きせずに止める
    - 削除・画面共有・参加者・コースの設定はしない
    - STEP の活動のマニュアル（[STEP Docs](https://step-docs.siststep.workers.dev/)。STEP Learn の使い方・かけでじ・ドキュメントの書き方など）について聞くと、AI が意味で検索して読み、答えの最後に「実際のドキュメント」として、使ったページへのリンク（`https://step-docs.siststep.workers.dev/<docs からのパス。拡張子なし・小文字>/`）を付ける。パスワードなどは取り込むときに伏せ、AI は実際のドキュメントで確かめるよう案内する。検索語の埋め込みは OpenRouter の Qwen3 Embedding 8B で行い、使用量は OpenRouter の月の上限に数える（利用者の週の枠には数えない）。取り込み方は下の「STEP Docs を AI エージェントに取り込む」
    - チャットを始めるときにモデルを選び（API キーを設定した提供元のモデルだけ）、その会話の途中では変えない。チャットは 1 人に 1 つで、閉じるとその場で消え、開き直せない。閉じずに置いたチャットも最後の発言から 5 日で消える
    - 会話は、やり取りの続きに文脈を渡すためだけにサーバーへ保存する。`SESSION_SECRET` から導いた鍵で AES-256-GCM で暗号化し、管理者にも中身は見せない
    - 呼び出しのたびに使用量を記録し、提供元ごとの週の枠（管理 > AI の月の上限を日割りして、直近 4 週間に使った人数で割ったもの）を使い切ると、その週は使えない
    - 「難しい依頼」で答える Claude Sonnet 5.5 には、Claude 全体の枠とは別に、Sonnet だけの週の枠がある（Claude 全体の 1 人あたりの枠に対する割合。管理 > AI で設定し、保存するまでは 50%）。Sonnet で使った分は Claude 全体の枠にも数え、Sonnet だけの枠を使い切っても Claude Haiku 5.5 では続けられる
    - パネルの入力欄の下に今週の使い具合を出し、押すと枠ごと（Claude 全体・Sonnet のみ）の使った割合とリセットの日時を開く
  - 小テスト：セクションに「小テスト」アイテムを追加すると、学生が問題に答えて、その場で採点の結果を受け取れる。採点は正解との照合で行い、AI は使わない。Moodle モードでも、Moodle の小テストの活動とは別の、STEP Learn だけにある種類のアイテムとして使える（下の「Moodle モード」）
    - 出題の形式は 7 つ: 選択（選択肢から 1 つ選ぶ）、出力の予測（コードを見て実行結果を入力する。行末の空白・前後の空行・全角と半角の違いは区別しない）、並べ替え（ばらばらに出した行を正しい順に並べる。ドラッグか上下のボタンで動かす）、バグ探し（コードの間違っている行を選ぶ）、実行の順番（行が実行される順に、行を押してたどる。関数の呼び出しや繰り返しの流れを確かめる）、字下げ（字下げを消して出したコードに、行ごとのボタンで字下げを付け直す。空白の数ではなく深さが合っていれば正解）、変数の追跡（繰り返しの各回での変数の値を表に書く。空白と引用符の種類の違いは区別しない）。問題ごとに解説を書ける
    - 教師は追加したあとの編集画面で、問題（1 アイテムに 50 問まで）、合格にする正解の割合（保存するまでは 80%）、不正解だった問題の正解と解説を見せるかを決める。見せないと、採点のあとに出すのは問題ごとの正誤と、正解した問題の解説だけになる。問題と設定は `quiz_items` に置く（問題は JSON）
    - 学生に出す画面の見た目を、アイテムごとに「標準」と「ゲーム」から選べる（`quiz_items.look`。Moodle モードでは `extra_items` の中身）。「ゲーム」は中学生向けで、出題の形式ごとの動物のキャラクター（選択＝フクロウ、出力の予測＝ネコ、並べ替え＝ペンギン、バグ探し＝カエル、実行の順番＝ウサギ、字下げ＝カニ、変数の追跡＝リス）が答え方を案内し、問題を 1 問ずつのステージにして道のりを進む。結果は星（全問正解で 3 つ、合格で 2 つ、1 問でも正解なら 1 つ）と「ふりかえり」で出す。問題・採点・受け直しは標準と同じで、採点は最後にまとめて行う（1 問ずつ正誤を返すと、答えを変えながら正解を探せるため）。教師の受験結果の画面は、どちらの見た目でも標準のまま
    - 「ゲーム」は、three.js で描く、画面全体を使う 3D のゲームになっている（`src/quiz-world.ts`。この見た目の小テストを開いたときだけ読み込む）。「ゲームスタート」を押すと画面全体がゲームになり、学生は一人称の視点で（W A S D で歩き、マウスで見まわし、スペースキーでジャンプ。左右の矢印キーでも向きを変えられる。スマホは左下のスティックで歩き、画面をなぞって見まわす）、たいまつの灯る石のダンジョン（石積みの壁・石だたみ・木のはり・手もとの明かり）を進む。マップは開くたびにランダムに作る（スタートからゴールまで、問題の数 + 1 の部屋を、同じ場所を通らない道としてつなぎ、問題のない寄り道の部屋を足す）。右上のミニマップには、歩いた部屋と、そこから見える出入り口だけが出る。部屋には宝石が浮かび、寄り道の部屋には宝箱か泉がある（宝石は点数にならない）。スタートからゴールまでの道は問題ごとの扉で区切られていて、扉の前の部屋に、その問題が実物として置いてある。問題文は扉の右の壁の石板に書いてあり、答えは、部屋の中のものに照準を合わせてクリック（スマホはタップ。E キーでもよい）で動かして入れる。手の届く所まで歩いて近づかないと動かせない。形式ごとの答え方は、選択が「答えの玉を持ちあげて、扉の横のこたえの台座へ運んで置く」、並べ替えが「棚のブロックを持ちあげて、入れたい場所のブロックを押す」、バグ探しが「まちがいのある行のブロックを押す（虫がとまる）」、実行の順番が「実行される順にブロックを押す（押した順番がブロックに付く。1 つもどす・やりなおすの石のボタンがある）」、字下げが「ブロックの右はし・左はしを押して、左右にずらす」、出力の予測が「黒板をクリックして、キーボードで書く」、変数の追跡が「表のますをクリックして書く（Enter で次のますへ）」。答えたら、扉の右の柱のレバーを引くと、サーバーがその問題の答えを確かめ、正解なら扉が開いて先へ進める。まちがいなら扉は開かず、扉の番の動物が首を振る（何度でも答え直せる）。一度まちがえてから正解したときは、問題の解説を画面に出す。最後の扉の先のゴールで宝箱を開けると「こたえあわせ」になる。点数は、問題ごとの最初の答え（最初にレバーを引いたときの答え）で数える（扉は正解するまで開かないので、最後の答えはいつも正解になるため）。部屋の置き物（台座・玉・棚とブロック・石板・黒板・レバー・扉・宝箱・たる・木箱・柱など）は、角を丸めた箱・回転体・面取りした額縁を組み合わせた 3D モデルで作っている（外部のモデルのファイルは使わない）。N キー（か画面の上の「ノート」）で、同じ問題を文字で読んで答えられるノートが開く（石板に収まらない長い問題と、キーボードだけで答えるとき用。ノートで入れた答えは、部屋の実物にも映る）。Tab キーでは、部屋の動かせるものを順に選べ（選ぶと視点がそのものへ向く）、Enter で動かせる。Esc などでマウスの固定が外れると「ひとやすみ」のメニューになり、「つづける」か「やめる」を選ぶ。スタートの画面の「3D を使わずに答える」を押すと、3D を片付けて、下の 2D の道のりで答える形に切り替わる。結果は、動物が並んで跳ね、星が 1 つずつ現れ、合格なら紙吹雪が降る。WebGL を使えない端末と、動きを減らす設定の端末では、2D の道のり（1 問ずつのステージと、最後にゴールのステージ）で出す
    - 2 つのモードで使い回すため、受験と受験結果の処理（`src/routes/quiz/handlers.tsx`）は DB を開かず、モードごとの設定の読み出し・受験の記録・権限の確認を `QuizBackend` と `QuizStore`（`src/lib/quiz-store.ts`）として受け取る（通常モードは `src/routes/quiz/backend.ts` と `src/lib/quiz-items.ts`、Moodle モードは `src/moodle-mode/quiz.ts`）
    - 学生は何度でも受け直せる（1 人がアイテム 1 つに 100 回まで）。受験のたびに答えと正誤を `quiz_attempts` に残し、あとから問題や合格の割合を変えても、受けたときの点数と合否は変えない。並べ替えの行は学生ごとに決まった順に混ぜ、開き直しても変わらない
    - 完了の条件に「合格したら完了」を選べる。アクセス制限では、いちばん高い正解の割合を評点として、合格・不合格を完了の状態として使える
    - 教師はアイテムの「受験結果」から、学生ごとのいちばん高い点数・受験の回数と、問題ごとの正答率（学生ごとのいちばん新しい受験で数える）、学生ごとの受験の中身（答えと正誤）を見られる。教師には解答の画面を採点のボタンなしで出す
  - ファイル自動配布：セクションに「ファイル自動配布」アイテムを追加し、編集画面でフォルダーごと（またはファイルや zip を選んで）アップロードすると、学生はアイテムの「VS Code で開く」を押すだけで、VS Code の拡張機能「STEP Learn for VSCode」（`vscode-extension/`。下の「VS Code の拡張機能」）がファイルを `ドキュメント/STEP Learn/<コース名>/<アイテム名>` に用意してフォルダーを開く。拡張機能がない人のために zip でもダウンロードできる
    - フォルダーの構成はそのまま配る。`.git`・`node_modules`・`__pycache__`・`.venv` などは外し、実行ファイル（.exe など）は受け付けない。同じ場所のファイルは置き換わる。1 アイテムに 500 個・合計 50MB まで（1 回のアップロードは 30MB まで）
    - アップロードは、ドラッグ＆ドロップするか選んだ時点で始まる。zip を選ぶかドロップすると、サーバーで展開して中身を配る（中身がすべて 1 つのフォルダーに入っていれば、そのフォルダーの中身。フォルダーの中にある zip は展開せずにそのまま配る）。ファイルの名前は UTF-8 のほか、日本語の Windows で作った zip（Shift_JIS）も読める。パスワード付きの zip には対応しない
    - 2 回目からは前に用意したフォルダーを開く。教師がファイルを足したり更新したりしていれば、取り込むかを聞き、学生が書き換えたファイルは上書きしない
    - 「VS Code で開く」のリンクには、その学生とアイテムに限った鍵（数分で切れ、1 回だけ使える）を付ける。拡張機能はそれを、ファイルの一覧と受け取るための鍵（15 分）に引き換える（`/api/vscode/claim`）。鍵は `SESSION_SECRET` から導いた鍵で署名し、DB には保存しない
    - データを同期する（オプション）：編集画面の「データを同期する」を有効にすると、学生が VS Code でファイルを保存するたびに、拡張機能がその内容を STEP Learn に送り（`/api/vscode/sync`）、ファイルごとの変更履歴として残す。教師はアイテムの「変更履歴」から、学生ごとに、保存のたびの差分（1 つ前の記録との違い。最初の記録は配ったファイルとの違い）とその時点のファイル全体を見られる。学生も自分の変更履歴を見られる
      - 学生には、アイテムの画面と、VS Code で最初に開くときの確認（同意するまで送らない）で、記録されることを知らせる。同期しているあいだは VS Code のステータスバーに表示が出る
      - 記録するのは文字のファイル（1 つ 256KB まで）で、`.git`・`node_modules` などは除く。新しく作ったファイルと、消したファイルも記録する。1 人がアイテム 1 つに残せるのは合計 30MB まで。中身は gzip で縮めて DB（`bundle_sync_versions`）に置き、アイテムや利用者を消すと一緒に消える
      - 同期の鍵（180 日）は「VS Code で開く」のときに渡す。有効にする前に開いた学生も、次に VS Code でそのフォルダーを開いたとき（開いたままなら 5 分以内）に確認が出て、送り始める。同期を止めても、それまでの変更履歴は残る
  - コーディングエージェント：セクションに「コーディングエージェント」アイテムを追加すると、学生はアイテムの「VS Code で使う」から、VS Code の拡張機能「STEP Learn for VSCode」のサイドバーで AI（教師が選んだモデル）に頼んで、開いているフォルダーのファイルを読み書きしながらプログラムを書いてもらえる。授業で使うためのもので、AI が書く内容は制限しない
    - 教師は編集画面で、使える期間（開始と終了の日時。6 時間まで）と 1 人あたりの上限（USD）を決める。アイテムの説明は学生に見せるほか、AI にも渡す
    - 教師は編集画面の「AI のモデル」で、Claude Haiku 5.5（既定）・Claude Sonnet 5.5・Claude Opus 5.5 か、OpenRouter のモデルを選ぶ。OpenRouter のモデルは、サーバーが OpenRouter のモデル一覧（`/api/v1/models`）を 1 時間キャッシュして並べ、名前と ID の検索で絞り込める。ツールを呼べないモデルと、コンテキストが 64K トークンに満たないモデルは出さない。モデルにカーソルを重ねると、料金・コンテキストの長さ・要約する長さが出る。選んだときの料金とコンテキストの長さを `agent_items.openrouter_model` に残し、使った額は OpenRouter が返す額（なければ残した料金）で数える
    - 教師は編集画面の「AI への指示」に、このアイテムの AI がどの依頼でも守る決まり（答えをそのまま書かずヒントを出す、使ってよい書き方など。8,000 文字まで）を書ける。学生には表示せず、サーバーがシステムプロンプトに足して、既定の進め方より優先させる（`agent_items.instructions`）
    - 使えるようにするのは管理者だけ。管理者がアイテムの編集画面で、選んだモデルの提供元（Anthropic か OpenRouter）の API キーとアイテム全体の上限（USD）を入れるまで、誰も使えない。キーはアイテムごとで、`CLAUDE_API_KEY`・`OPENROUTER_API_KEY` とは別に請求される。2 つの提供元のキーを両方入れておくこともできる。保存するときに、そのキーを使えるかを提供元に確かめる。キーは `SESSION_SECRET` から導いた鍵で暗号化して `agent_items` に置き、画面には末尾の 4 文字だけを出す。管理 > コーディングエージェントに、キーを入れていないアイテムを先に並べる
    - 「VS Code で使う」のリンクには、ファイル自動配布と同じ数分で切れる 1 回だけの鍵を付け、拡張機能はそれをアイテムと利用者に限ったトークンに引き換える（`/api/vscode/agent/claim`）。トークンは SHA-256 のハッシュを `agent_tokens` に置き、1 人がアイテム 1 つで持てるのは 5 つ（PC 5 台）まで。使うたびに、本人が今もそのアイテムを開けるかを確かめる
    - 拡張機能は依頼ごとに会話を STEP Learn に送り（`/api/vscode/agent/messages`）、STEP Learn がアイテムの API キーで Anthropic か OpenRouter を呼んで、応答をそのまま流して返す。モデル・システムプロンプト・ツールの一覧・出力の上限はサーバーが決め、拡張機能から変えられない。ツール（フォルダーの一覧・読む・探す・書く・書き換える・コマンドの実行・VS Code の「問題」を読む・学生がターミナルで実行した出力を読む）は学生の PC で拡張機能が実行し、開いているフォルダーの外は扱わない。AI に渡すツールは、拡張機能が実行できると伝えてきたものだけにする。コマンドは毎回学生に確かめてから実行する。依頼には、学生がエディターで開いているファイルの場所と選んでいる行を拡張機能が付ける
    - 呼び出しのたびに使った額を `agent_usage` に記録し、本人の上限かアイテム全体の上限に達すると使えなくなる。学生には額ではなく使った割合だけを見せ、教師は編集画面で学生ごとの額を見られる。会話の入力が要約する長さに達したら、拡張機能が会話を要約に置き換えて続ける（`/api/vscode/agent/summarize`）。要約する長さは、Claude Haiku 5.5 では 80K トークン（1 回の入力が 100K トークンを超えると料金が上がるため）、ほかのモデルでは、コンテキストの長さから 1 回の出力の分を引いた 9 割（Sonnet と Opus は 871K トークン）。会話はサーバーに残さず、学生の PC に、開いているフォルダーごとに保存する
    - 拡張機能のサイドバー（右側のサイドバーの「STEP Learn」。VS Code 1.106 より前では左のバー）は、使える期間のあいだだけ出る。非表示やアクセス制限で開けないときと、期間の外では隠れる
    - 通常モードだけで使える（Moodle モードにはない）
、教師がブラウザから画面をライブ配信でき、参加者はアイテムを開くと別タブいっぱいに映像を視聴できる（最大 1920×1080・30fps、回線と画面の動きに応じた可変ビットレート）
- **管理画面**（管理者、`/admin`）：ユーザーのロール変更、全コースの一覧と作成、操作ログ
  - 操作ログ（管理 > 操作ログ）：誰が・いつ・どの IP アドレスから何をしたかを残し、種類とユーザーで絞り込める。記録は `operation_logs` に置き、種類ごとに保存期間を変える（記録の対象と種類は `src/lib/operation-log.ts` の `RULES`、保存期間は `src/lib/types.ts` の `LOG_RETENTION_DAYS`）

    | 種類 | 記録するもの | 保存期間 |
    | --- | --- | --- |
    | 閲覧 | コース・アイテム・画面共有を開いた、ファイル・zip を開いた、教師が学生の提出・変更履歴を見た | 90 日 |
    | 操作 | ログイン（失敗も。Microsoft アカウントでのログインも）・ログアウト、教材の追加・編集・並べ替え・表示の切り替え、コースの設定、完了の切り替え、コードの提出・採点、AI への依頼など | 365 日 |
    | 重要な操作 | 削除（コース・セクション・アイテム）、コースの作成、参加者の追加・除外・ロールの変更、ユーザーのロールの変更、新規登録、パスワード・プロフィールの変更、Microsoft アカウントの連携・解除、AI の上限の変更 | 消さない |

  - 何を変えたかの中身（本文や入力した値）は残さない。削除したものは、削除した時点の名前を残す
  - 画面を開いた記録は、ホバーしたときの先読みや開いている画面の自動更新を数えず、実際に開いたときだけ残す。コードの自動保存と実行は数が多いので残さない
  - 期限を過ぎた記録は、記録するときに 1 時間に 1 回まとめて消す
  - Moodle モードでは残さない（操作は Moodle の Web サービスを通るので Moodle のログに残る。ただし閲覧は残らない）
- **テーマ**：既定はライト。ヘッダーのユーザーメニューで選んだときだけダークにし、選択はブラウザ（localStorage）に保持する

## 設計方針

| 方針 | 実装 |
| --- | --- |
| 速さ | SSR（hono/jsx）＋ 小さなクライアント JS。リンクとフォーム送信を fetch に置き換え、ホバー時の先読みと View Transitions で再読み込みなしに遷移する（SPA）。JavaScript は必須で、無効なブラウザには有効化を求める案内だけを表示する |
| DB | `better-sqlite3`（WAL モード）＋ Drizzle ORM。DB サーバーは要らない。テーブル定義は `src/lib/schema.ts` で、マイグレーションは drizzle-kit で生成する。クエリも Drizzle のクエリビルダーで書き、結果に型が付く |
| コスト | 必要なのは Node.js が動くサーバー 1 台だけ。DB も教材ファイルも同じサーバーのディスクに置く |
| 依存の少なさ | ランタイム依存は `hono`・`@hono/node-server`・`nodemailer`（確認メールの SMTP 送信）・`better-sqlite3`・`drizzle-orm`・`socket.io`（画面共有の中継）・`zod`（入力の検証。同じ規則をブラウザでも使うので、ブラウザ側は軽量版の `zod/mini`）・`@anthropic-ai/sdk`（Claude の呼び出し）・`yauzl`（ファイル自動配布でアップロードされた zip の展開）だけ。ネイティブアドオンの `better-sqlite3` 以外は 1 ファイルにバンドルされる。ブラウザ側のライブラリは入力の検証の `zod/mini` と、Markdown エディターの CodeMirror、コードのエディターの Emmet（HTML の略記の展開）と Prettier（コードの整形）、ログイン画面の 3D アニメーションと小テストのゲームの見た目の three.js、PDF ビューアーの pdf.js だけ。CodeMirror はエディターのある画面でだけ（HTML / CSS / JavaScript / Python の文法と Emmet は、コーディング問題とその編集画面でだけ）、Prettier は整形したときだけ、three.js はログイン前の画面と、ゲームの見た目の小テストを開いたときだけ、pdf.js は PDF のアイテムをビューアーで開いたときだけ読み込む |
| セキュリティ | PBKDF2（60 万回、ログイン時に旧設定のハッシュを再計算）、推測されやすいパスワードの拒否、ログイン失敗と確認メール・再設定メール送信のレート制限、登録画面と再設定画面からメールアドレスの登録有無がわからない設計、セッション Cookie は HMAC-SHA256 で署名しトークンは SHA-256 で保存、Microsoft アカウントでのログインは認可コードフロー（PKCE・state・nonce）で確かめ、持ち主を確認済みのメールアドレスだけを既存のアカウントとの照合に使う、CSRF 対策は Origin 検証と SameSite=Lax、ファイルは権限を確認したうえで配信（PDF と画像以外は添付として返す） |

## 開発

Node.js 24 以上が必要です。

```sh
npm install
npm run dev          # http://localhost:5173
```

- 初回起動時に `migrations/` のスキーマが自動で適用され、`data/step-learn.db` が作られます
- アップロードしたファイルは `data/files/` に保存されます
- データを初期化したいときはサーバーを止めて `data/` を削除してください
- SMTP を設定していない間は、確認メールは送信されずにサーバーのログに出力されます

最初の管理者は CLI で作成します（CLI は `npm run build` で生成されます）。

```sh
npm run build
npm run user:create -- --email admin@example.com --name "管理者" --username admin
```

```sh
npm run typecheck
npm run lint          # oxlint
npm run format        # Prettier で整形（確認だけなら format:check）
```

## 本番運用

```sh
npm ci
npm run build        # dist/client（CSS/JS）と dist/server/index.js を生成
npm start            # = node dist/server/index.js
```

設定は環境変数か `.env` で行います（`.env.example` を参照）。

- `PORT`：待ち受けポート（既定 3000）
- `APP_ORIGIN`：nginx や Caddy などのリバースプロキシの後ろで動かす場合は、公開 URL（例 `https://lms.example.com`）を必ず設定してください
- `SESSION_SECRET`：セッション Cookie の署名鍵（32 文字以上）。未設定なら `data/session-secret` を自動生成して使います。変更すると全員がログアウトされ、保存中の AI のチャットも読めなくなるので消えます
- `SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASS` / `MAIL_FROM`：確認メールの送信に使う SMTP サーバー。`SMTP_HOST` を設定する場合は `MAIL_FROM` と `APP_ORIGIN` も必須です
- `OPENROUTER_API_KEY`：[OpenRouter](https://openrouter.ai/) 経由のモデルに使う API キー。AI エージェントに送られた発言が STEP Learn の作業と関係あるかの判定（Span-01 Lite、判定できなかったときは Span-02）と、STEP Docs の検索（Qwen3 Embedding 8B）に使い、未設定なら判定を省き、STEP Docs はページの一覧から AI が選んで読みます。DeepSeek V4.1 Flash は予備で、Claude を使えないときと、Anthropic の今月の使用量が月の上限の 60% を超えたときだけ、会話で選べるようになり、コーディング問題の採点もこちらに切り替わります（`src/lib/ai-models.ts` の `AI_RESERVE_MODELS`）。Jev は一時的に止めています（`AI_PAUSED_MODELS`）
- `CLAUDE_API_KEY`：Claude（Claude Haiku 5.5・Claude Sonnet 5.5）に使う [Anthropic](https://platform.claude.com/) の API キー。未設定ならこれらのモデルは使えません。AI エージェントの会話とコーディング問題の採点はふだん Claude Haiku 5.5 を使い、AI のパネルで「難しい依頼」を選んで送った発言だけ Claude Sonnet 5.5（考える深さ high）が答えます（`AI_HARD_TASK_MODELS`）。学生が提出したコードと問題文・採点基準が Anthropic の API（DeepSeek に切り替わったあとは OpenRouter）に送られます
- 使うモデルは `src/lib/ai-models.ts` に並べたものだけです。月の上限（USD）は提供元ごとに管理 > AI で設定します（保存するまでは OpenRouter が $3、Anthropic が $15）。コーディング問題の採点にかかった額も採点に使ったモデルの提供元の使用量に数え、月の上限に達している間は、提出しても自動では採点しません
- `MICROSOFT_CLIENT_ID` / `MICROSOFT_CLIENT_SECRET` / `MICROSOFT_TENANT`：Microsoft アカウントでのログインに使う Microsoft Entra ID のアプリ（下の「Microsoft アカウントでのログイン」）。`MICROSOFT_CLIENT_ID` を設定する場合は `MICROSOFT_CLIENT_SECRET` も必須です。`MICROSOFT_TENANT` は既定で `common`（組織と個人のどちらのアカウントでも可）で、`organizations`（組織のアカウントだけ）・`consumers`（個人のアカウントだけ）・テナント ID（その組織だけ）も選べます。Moodle モードでは使いません
- `AI_EMAIL_DOMAIN`：AI エージェントを使えるメールアドレスのドメイン（`@` より後ろの完全一致）。未設定なら `sist.ac.jp`
- `SANDBOX_URL`：学生が書いたコードを実行する sandbox のコンテナ（下の「コードを実行する sandbox」）の接続先。未設定ならコードの実行は使えません。Docker Compose で動かす場合は自動で設定されます
- `TRUST_PROXY`：リバースプロキシの後ろで動かす場合は `1` にしてください。`X-Forwarded-For` からクライアントの IP を取ってレート制限に使います（未設定だと全員がプロキシの IP として扱われます）
- 画面共有は `/socket.io/` で WebSocket を使います。リバースプロキシでは WebSocket の Upgrade を通してください（nginx なら `proxy_http_version 1.1;` と `Upgrade` / `Connection` ヘッダーの転送）。通らない場合は HTTP のロングポーリングに切り替わって動きますが、遅延と負荷が増えます
- 配信中の状態と、コードの採点の順番待ちはプロセスのメモリに持つため、複数のプロセスやサーバーに分散させないでください。採点の途中で再起動すると、その提出は「採点できませんでした」になり、教師が採点し直せます
- 実行時に必要なのは `dist/`・`migrations/`・`migrations-moodle/`（Moodle モードのとき）・`.env` と、`better-sqlite3` を入れた `node_modules` です（`npm ci --omit=dev` で入ります）。起動したディレクトリを基準に読み込みます
- SQLite・セッション署名鍵・（ローカル保存時の）教材ファイルは、起動したディレクトリの `data/` に保存されます（変更はできません）。**このディレクトリをバックアップ対象にしてください**

### Microsoft アカウントでのログイン

[Microsoft Entra 管理センター](https://entra.microsoft.com/) の「アプリの登録」で、次のようにアプリを登録します。

1. 「新規登録」で、サポートされているアカウントの種類を「任意の組織ディレクトリ内のアカウントと個人用 Microsoft アカウント」にする（`MICROSOFT_TENANT` で絞るなら、それに合わせる）
2. リダイレクト URI に「Web」で `<APP_ORIGIN>/auth/microsoft/callback`（例 `https://lms.example.com/auth/microsoft/callback`）を登録する。手元の開発では `http://localhost:<ポート>/auth/microsoft/callback` も足す
3. 「証明書とシークレット」でクライアントシークレットを作り、値を `MICROSOFT_CLIENT_SECRET` に、概要の「アプリケーション (クライアント) ID」を `MICROSOFT_CLIENT_ID` に設定する。シークレットには期限があるので、切れる前に作り直してください
4. 「トークン構成」で、ID トークンに省略可能な要求 `email` と `xms_edov` を追加する。`xms_edov` がないと、組織のアカウントのメールアドレスを確かめられず、既存のアカウントとの照合と新規登録ができません（アカウント画面からの連携はできます）

- 戻り先の URL は `APP_ORIGIN`（なければ要求の URL）から作ります。リバースプロキシの後ろでは `APP_ORIGIN` を設定してください
- サインイン画面では毎回アカウントを選ばせます（教室の共用の端末で、前の人のアカウントでログインしないように）
- Microsoft アカウントとの結び付きは、メールアドレスではなく Microsoft のテナント ID とオブジェクト ID で覚えるので、あとから Microsoft 側のメールアドレスが変わってもログインできます

### STEP Docs を AI エージェントに取り込む

STEP Docs の本文は、非公開のリポジトリ（[sist-step/step-docs](https://github.com/sist-step/step-docs)）の `src/content/docs` にあります。step-learn は公開リポジトリなので、本文も索引もこのリポジトリとイメージには入れません。

1. step-docs の `main` の docs が変わると、step-docs のワークフロー（`.github/workflows/ai-index.yml`）が、beta のサーバーの self-hosted ランナーで動く
2. ワークフローは step-docs の docs と、step-learn の `scripts/docs-index.ts` だけを checkout し、索引（本文を見出しごとに分けた断片と、そのベクトル）をサーバーの専用ディレクトリ（既定 `/srv/step-learn/ai-docs`）の `step-docs.json` に書く
3. STEP Learn のコンテナは、`compose.yaml` でそのディレクトリを `/app/ai-docs` に読み取り専用でマウントして読む。ファイルが変わったら次の検索のときに読み直すので、再起動は要らない

- 中身が変わっていない断片は前の索引のベクトルを使い回すので、API を呼ぶのは変わった部分だけです（全部を作り直しても 1 円にもなりません）
- パスワードなどは、`PW: xxx` / `ID：xxx` のようにラベルを付けた値（パスワード・ID・ユーザー名など）と、その値が同じページのほかの場所に書かれた箇所、API キーの形の文字列、URL に含まれるパスワード、Google のフォーム・ドライブと Discord のリンクを `[非公開: 元のドキュメントを参照]` に置き換えてから索引に入れます。AI はそこを推測せず、実際のドキュメントを見るよう案内します。ラベルなしで文中にだけ書かれたものは見つけられないので、`--dry-run` で確かめてください
- 画像は、docs サイトがログイン必須で表示できる URL がないため、`（画像: 説明）` に置き換えます
- 索引がないあいだは、AI エージェントはドキュメントを読めないことを伝えます
- `scripts/docs-index.ts` の索引の形を変えたら、step-docs の Actions から AI の索引のワークフローを手動で実行し直してください

準備（最初に一度）:

1. beta のサーバーで、ランナーのユーザーが書けて、コンテナ（`node` ユーザー）が読めるディレクトリを作る。例: `sudo mkdir -p /srv/step-learn/ai-docs && sudo chown <ランナーのユーザー> /srv/step-learn/ai-docs`
2. step-docs のリポジトリに、同じサーバーの self-hosted ランナー（ラベル `self-hosted` / `linux` / `beta`）を登録する。step-learn のランナーはリポジトリごとの登録なので、step-docs からは使えません
3. step-docs のリポジトリに Environment `beta` を作り、Secret `OPENROUTER_API_KEY` を登録する。ディレクトリを変えるときは、step-docs の変数 `AI_DOCS_DIR` と step-learn の変数 `DEPLOY_AI_DOCS_DIR` を同じ値にする

手元で試すとき（開発サーバーは `ai-docs/` を読む。`ai-docs/` は Git の対象外）:

```sh
npm run docs:index -- --docs ../step-docs/src/content/docs --dry-run    # 取り込むページと伏せる箇所を確かめる（何も書き込まない）
npm run docs:index -- --docs ../step-docs/src/content/docs --out ai-docs # .env の OPENROUTER_API_KEY で索引を作る
```

### ユーザーを CLI で作成する

```sh
npm run user:create -- --email admin@example.com --name "管理者" --username admin [--role admin|teacher|student]
```

- `--role` を省略すると管理者になります
- `--username` は半角英数字と `.` `_` `-` で 3〜30 文字です
- パスワードは対話的に入力します。パイプで渡した場合は 1 行目を使います（例 `cat password.txt | npm run user:create -- ...`）
- Web の新規登録と同じパスワードの基準を満たす必要があります

### Moodle から移行する

Moodle のコースバックアップ（.mbz）から、コース・セクション・アイテム・参加者を取り込みます（CLI は `npm run build` で生成されます）。

```sh
npm run moodle:import -- backup.mbz --dry-run   # プレビューだけを表示する
npm run moodle:import -- backup.mbz             # プレビューを表示し、確認してから取り込む
```

- Moodle の「バックアップ」でコースごとに書き出した .mbz を使います。参加者も移すときは「ユーザーを含める」をオンにし、「匿名化」はオフにしてください。展開したディレクトリも指定できます
- 取り込む前に、作られるセクション・アイテム・参加者と、取り込まないもの・変換で失われるものをプレビューに表示します。`--yes` で確認を省き、`--verbose` で学生をすべて表示します
- 1 回の実行で新しいコースを 1 つ作ります。同じバックアップを 2 回取り込むとコースが 2 つできます（プレビューで警告します）

| Moodle | STEP Learn |
| --- | --- |
| ページ・ラベル・ブック | ページ（HTML を Markdown に変換。画像は「（画像: 名前）」、表は「 \| 」区切りの行になる。ブックは章ごとの見出しを付けて 1 ページにまとめる） |
| URL | リンク（http / https のみ） |
| ファイル | ファイル（メインのファイル 1 つ） |
| フォルダ | 中のファイルごとにファイルのアイテム |
| 課題・小テスト・フォーラムなど | 取り込まない |
| 表示 / 非表示、完了トラッキング | 学生に非表示、完了の条件（「閲覧したら完了」は「開いたら完了」、それ以外は「学生が自分で完了にする」） |
| アクセス制限（日付・条件） | 取り込まない（制限なしで表示される） |
| 教師・編集権限のない教師・マネージャー / 学生 | 教師 / 学生（削除・停止されたユーザーは除く） |

- 同じメールアドレスのユーザーがすでにいれば、そのユーザーを参加者に加えます。いなければ作成します（Moodle のユーザー名が規則に合い、空いていれば引き継ぎます）
- Moodle のパスワードは引き継げません。新しく作ったユーザーには、ログイン画面の「パスワードを忘れた場合」からパスワードを設定してもらってください（SMTP の設定が必要です）
- 学生の完了状況や評定は取り込みません

#### Moodle から直接取り込む

.mbz を使わず、Moodle の Web サービスからコースを読んで取り込むこともできます。取り込むのはコース・セクションと URL・ファイル・フォルダーだけです（参加者・ページ・ラベル・課題などは取り込みません）。

```sh
MOODLE_MIGRATE_URL=https://moodle.example.ac.jp MOODLE_MIGRATE_TOKEN=<トークン> \
  npm run moodle:migrate -- 12 13 --dry-run   # コース ID 12 と 13 のプレビューだけを表示する
```

- Moodle に `moodle/local_steplearn/` のプラグインが入っている必要があります（Moodle モードと同じもの）
- トークンは、すべてのコースを見られるアカウント（システムのコンテキストで「マネージャー」を割り当てたアカウントなど）のものを、外部サービス「STEP Learn」で発行します
- コースごとにプレビューを表示し、確認してから取り込みます。`--yes`・`--verbose` は `moodle:import` と同じです
- サブセクションは、親のセクションのすぐ後ろに「親 › 子」という名前のセクションとして並べます
- Moodle モードで追加した、STEP Learn にしかない種類のアイテムは引き継ぎません

### Moodle モード（完全移行までの一時的な運用）

`MOODLE_URL` を設定すると、STEP Learn を Moodle 5.1 のフロントエンドとして動かします。データはすべて Moodle にあり、STEP Learn は画面だけを受け持ちます。

- ログインは Moodle のログイン画面で行います（ログイン画面の「旧STEP Learnでログイン」から移動）。手動のアカウントでも Microsoft アカウントでもログインでき、ログインすると STEP Learn と Moodle の両方でログインした状態になります
- Moodle のログイン画面とダッシュボードに「新しい STEP Learn を使う」ボタンを出せます（プラグインの設定でオンにします）。押すとそのまま STEP Learn にログインします
- ログアウトすると Moodle からもログアウトします。Moodle の画面でログアウトしたときも、STEP Learn から抜けます（`MOODLE_BACKCHANNEL_SECRET` を設定した場合）
- Moodle のセッションが時間切れになったときや、管理者に強制ログアウトされたときも、STEP Learn から抜けます（確認は 1 分おきで、次に画面を開いたときにログイン画面に戻ります）。STEP Learn を使っている間は Moodle のセッションも延長されます
- STEP Learn の画面で扱うのは URL とファイルの活動だけです。課題・小テストなどのほかの活動は「Moodle で開く」から Moodle の画面で使います（ラベルは本文をセクションの中に表示します）
- 教師は、セクション・リンク・ファイルの追加・編集・並べ替え・表示の切り替え・削除を STEP Learn の画面でできます。参加者・コースの設定・アカウント設定・管理は Moodle の同じ画面に移ります
- 教師は、セクション・活動のアクセス制限も STEP Learn の画面で編集できます（画面と条件は通常モードと同じ。評点は Moodle の評点の項目、ユーザープロフィールは Moodle の標準の項目と独自の項目、条件の種類はサイトで有効なものだけ）。グループ・グルーピングなど STEP Learn で足せない条件は、説明だけの行として表示し、保存しても残ります（行ごと消すことはできます）。学生に出す判定と説明は Moodle のものを使います
- コースページは、コースフォーマットが「タイル」（format_tiles）と「折りたたみ型トピック」（format_topcoll）のコースではその見せ方に合わせます。ほかのフォーマットは、すべてのセクションを開いた一覧です
  - タイル: 一般セクションの下にセクションをタイルで並べ、押すとそのタイルの行のすぐ下にセクションを開きます（同時に開けるのは 1 つで、別のタイルを押すと前のセクションは閉じます）。タイルのアイコン（STEP Learn のアイコンに置き換え）・写真・進捗の表示・サブタイルの設定に従います
  - 折りたたみ型トピック: セクションを開閉でき、開閉は Moodle の画面と同じく利用者ごとに記録されます。並べ方（最新の週を先頭に など）・現在のセクション・すべて開く/閉じる・1 つだけ開く・段組み・閉じたときの概要の表示の設定に従います（色やアイコンの設定は使いません）
- STEP Learn にしかない機能（新規登録・パスワードの再設定・Markdown のページ・CLI）は使えません
- 画面共有は、Moodle モードだけにある種類のアイテム（下）として追加できます。一覧や目次から開くと、新しいタブで画面共有の画面を開きます（Moodle の画面から開いたときも新しいタブで開きます）。視聴できるのはアイテムを開ける参加者、配信できるのはコースを編集できる人で、接続している間も確かめ直し、見られなくなった人の接続は切ります
- コーディング問題（コードを書いて提出し、AI が判定するアイテム）も、Moodle モードだけにある種類のアイテム（下）として追加できます。機能は通常モードと同じで、一覧や目次から開くと、新しいタブでエディターの画面を開きます。提出の一覧に並ぶのは提出した学生だけです（参加者は Moodle にあるため）。書きかけのコード・提出・採点は `data/moodle-mode.db` に置き、Moodle の評定には反映しません。完全移行では引き継ぎません。採点にかかった AI の使用量も `data/moodle-mode.db` に記録し、通常モードと同じく月の上限に達している間は自動では採点しません
- ファイル自動配布も、Moodle モードだけにある種類のアイテム（下）として追加できます。機能は通常モードと同じです。配るファイルの一覧と、データを同期するアイテムの変更履歴は `data/moodle-mode.db` に、ファイルの中身は教材ファイルと同じストレージの `moodle-mode/` の下に置きます。変更履歴の一覧に並ぶのは記録がある人だけです（参加者は Moodle にあるため）。完全移行では引き継ぎません
  - Moodle には、URL の活動ではなく専用の活動「ファイル自動配布」（`moodle/mod_stepbundle/` のプラグイン）を置きます。Moodle の画面で開くと STEP Learn のアイテムの画面に移り、Moodle の画面（活動の追加）からも作れます。このプラグインが Moodle に入っていないときは、アイテムを追加する画面にファイル自動配布を出しません
  - ごみ箱から戻した活動は、前に配っていたファイルにつながります。複製した活動とコピーしたコースの活動は、ファイルのない状態から始まります
  - 拡張機能から変更が届くたびに、送った学生の Moodle のトークンで、その活動が今も見えるかを確かめます（コースの情報と同じく 30 秒キャッシュします）。活動を消した（STEP Learn・Moodle のどちらの画面からでも）、非表示にした、学生がコースから外れた、Moodle のトークンの期限が切れた（STEP Learn にログインし直すと直る）ときは記録せず、拡張機能は「同期できません」と表示して止まります。ごみ箱から戻したり表示に戻したりしたあとは、学生が「VS Code で開く」をもう一度押すと再開します。Moodle に接続できないあいだは、拡張機能が 1 分ごとに送り直します
  - 専用の活動にする前の形（URL の活動）で残っているファイル自動配布は、教師がそのコースを開いたときに、Moodle の活動・配るファイルごと自動で削除します（学生には、それまでも一覧に出しません）
- 小テストも、Moodle モードだけにある種類のアイテム（下）として追加できます。Moodle の小テストの活動とは別のもので、出題の形式・採点・受け直し・教師の受験結果は通常モードと同じです。Moodle には STEP Learn へ移る URL の活動として置き、問題と採点の設定は `extra_items` の中身に、受験の記録は `data/moodle-mode.db` の `quiz_attempts` に置きます。点数は Moodle の評定に反映せず、「合格したら完了」と、アクセス制限の評点・合否の条件は使えません（完了とアクセス制限は Moodle の活動のものを使うため）。受験結果の一覧に並ぶのは受けた学生だけです（参加者は Moodle にあるため）。完全移行では引き継ぎません
- コーディングエージェントも、Moodle モードだけにある種類のアイテム（下）として追加できます。機能は通常モードと同じで、教師が編集画面で説明・AI への指示・使える期間・1 人あたりの上限を決め、管理者がアイテムの API キーと全体の上限を入れるまで使えません。説明・AI への指示と期間・上限は `extra_items` の中身に、API キーと全体の上限・トークン・使用量は `data/moodle-mode.db` の `agent_items`・`agent_tokens`・`agent_usage` に置きます。編集画面の利用状況に並ぶのは使った学生だけです（参加者は Moodle にあるため）。完全移行では引き継ぎません
  - 拡張機能から要求が届くたびに、その学生の Moodle のトークンで、活動が今も開けるかを確かめます（コースの情報と同じく 30 秒キャッシュします）。活動を消した・非表示にした・アクセス制限で開けない、学生がコースから外れた、Moodle のトークンの期限が切れた（STEP Learn にログインし直すと直る）ときは、拡張機能のサイドバーが隠れます
  - 管理 > コーディングエージェントには、Moodle に今もある活動だけを、キーを入れていないものを先に並べます（タイトルとコースは、開いた管理者のトークンで Moodle から読みます）
- AI アシスタントも使えます。使えるのは、`AI_EMAIL_DOMAIN` のメールアドレスで、Moodle のサイト管理者か、いずれかのコースを管理できる人です。AI が読み書きする教材は Moodle にあり、追加できるのはセクション・リンク・コーディング問題、変えられるのはセクションと、リンク・コーディング問題です（Moodle の活動の中身・アクセス制限は扱いません）。会話は `data/moodle-mode.db` に通常モードと同じく暗号化して置き、完全移行では引き継ぎません
- 管理（`/admin`。Moodle のサイト管理者だけが開けます）は、AI の月の上限と使用量、コーディングエージェントのアイテムの一覧の画面です。上限と使用量は通常モードとは別に `data/moodle-mode.db` に置きます。ユーザーとコースの管理は Moodle のサイト管理で行い、画面の右上から移れます
- Moodle モードだけにある種類のアイテム（`src/moodle-mode/extra-kinds.tsx` に定義する）は、中身を `data/moodle-mode.db` に保存し、Moodle には同じ位置に STEP Learn へ移る URL の活動（リンク先は `/m/<キー>`。ファイル自動配布だけは専用の活動）を置きます。並び順・表示・アクセス制限・完了は Moodle の活動のものを使います。URL の活動に置いた種類は、Moodle でコースをコピーしたときは、コピー先では開けません。完全移行では引き継ぎません
- STEP Learn 側の DB は `data/moodle-mode.db`（ユーザーの写し・セッション・暗号化したトークンと、Moodle モードだけにある種類のアイテムの中身、コーディング問題の書きかけのコードと提出、小テストの受験の記録、ファイル自動配布の配るファイルの一覧と変更履歴、コーディングエージェントの API キー・トークン・使用量、AI の使用量と月の上限・チャット）で、`data/step-learn.db` は作りも開きもしません。完全移行のときに引き継ぐ必要はありません

Moodle 側には、このリポジトリの `moodle/local_steplearn/` のプラグインを入れて設定します。ファイル自動配布を使うときは `moodle/mod_stepbundle/` も入れます。手順は [moodle/README.md](moodle/README.md) を参照してください。

| 環境変数 | 内容 |
| --- | --- |
| `MOODLE_URL` | Moodle の URL（例 `https://moodle.example.ac.jp`）。設定すると Moodle モードになります |
| `MOODLE_EXCHANGE_TOKEN` | ログインのコードを交換する専用アカウントのトークン（必須） |
| `MOODLE_BACKCHANNEL_SECRET` | Moodle でのログアウトの通知を検証し、STEP Learn からのログアウトに署名する鍵（32 文字以上。プラグインの設定と同じ値）。未設定なら通知を受け付けず、ログアウトのたびに Moodle の確認画面が出ます |

完全移行して Moodle モードを使わなくなったら、次を削除します。

- `src/moodle-mode/`・`migrations-moodle/`・`drizzle.moodle.config.ts`・`moodle/`
- `src/index.tsx` のモードの切り替え（`./app` だけを読み込む形に戻す）と、`src/server.ts`・`vite.config.ts` の `config.moodle` の分岐
- `src/lib/config.ts` の `moodle` / `moodleDatabasePath` / `moodleMigrate`、`src/lib/db.ts` の Moodle モードのガード、`src/components/style.tsx` の `moodle-mode.css`
- `src/moodle/remote.ts` と `src/cli.ts` の `moodle:migrate`、`src/lib/forms.ts` の `extraItemFields` / `extraItem` / `extraCode`、`src/lib/bundle.ts` の `BUNDLE_MODULE`、`src/client.ts` の `setKindOnly`
- コーディング問題を 2 つのモードで使い回すための分け方（`src/routes/code/handlers.tsx` の `CodeBackend`、`src/lib/code-store.ts` の `CodeStore`、`src/lib/code-grader.ts` の `createGrader`、`src/routes/code/views.tsx` の `CodePage`）は、通常モードの実装（`src/routes/code/backend.ts`・`src/lib/code-items.ts`・`src/lib/code-grading.ts`）だけになるので、まとめてかまいません
- `package.json` の `moodle:migrate` / `db:generate:moodle` / `db:check:moodle`、CI の「Check Moodle mode migrations」、`Dockerfile` の `migrations-moodle`、`.dockerignore` の `moodle`

### Docker で動かす

```sh
docker compose up -d --build   # http://127.0.0.1:3000
```

- 設定はリポジトリ直下の `.env` を読みます（`ENV_FILE` で別のパスを指定できます）
- `PORT` と `DATA_DIR` はコンテナ内で固定です。ホスト側のポートは `HOST_PORT`（既定 3000）で変えられます
- ポートは既定で `127.0.0.1` にだけ公開されます。外部へはリバースプロキシ経由で公開し、`APP_ORIGIN` を設定してください
- リバースプロキシが別のホストにある場合は、`HOST_BIND` で公開するアドレスを変えます（例 `HOST_BIND=192.168.0.10` や `0.0.0.0`）
  - Docker の公開ポートは ufw / firewalld の INPUT ルールを通りません。送信元をリバースプロキシに絞るには、iptables の `DOCKER-USER` チェーンかホストの外のファイアウォールで制限してください
  - 例：`iptables -I DOCKER-USER -p tcp -m conntrack --ctorigdstport 3000 ! -s <リバースプロキシの IP> -j DROP`
- SQLite とローカル保存の教材ファイルは Docker ボリューム `step-learn_data` に保存されます。**このボリュームをバックアップ対象にしてください**
- 一緒に起動する `sandbox` サービスは、学生が書いたコードを実行するコンテナです（下の「コードを実行する sandbox」）。ボリューム `step-learn_sandbox-socket` はアプリとの通信用のソケットを置くだけなので、バックアップは要りません

### コードを実行する sandbox

コーディング問題で学生が書いた Python は、アプリとは別のコンテナ（`sandbox/`、Compose の `sandbox` サービス）で実行します（`SANDBOX_URL` が未設定のサーバーでは、コーディング問題で Python を選べません）。HTML / CSS / JavaScript はサーバーでは実行せず、学生のブラウザの中の、STEP Learn とは別オリジンとして扱われる iframe（`sandbox` 属性）でプレビューします。`docker compose up` でアプリと一緒に起動し、アプリからは共有ボリュームの UNIX ドメインソケット（`SANDBOX_URL=unix:/run/sandbox/sandbox.sock`）で呼びます。

sandbox のコンテナには、次の制限をかけています。

- ネットワークにつながない（`network_mode: none`）。インターネットにも、アプリやホストのポートにも届きません
- ルートファイルシステムは読み取り専用で、書き込めるのは実行ごとの作業ディレクトリ（16MB の tmpfs）だけ。秘密情報・環境変数・データのボリュームは置きません
- ケーパビリティは、実行ごとに別の UID へ切り替えるための `SETUID` / `SETGID` 以外をすべて外し、`no-new-privileges` を付けます。コードを実行するプロセスは、どのケーパビリティも持たない一般ユーザーです
- コンテナ全体でメモリ 512MB・CPU 1 コア・256 プロセスまで
- 1 回の実行は、実時間 10 秒・CPU 時間 5 秒・メモリ 256MB・16 プロセス・出力 64KB（標準出力と標準エラー出力のそれぞれ）・ファイル 1 つ 8MB まで。超えたら止めます
- 同時に実行できるのは 4 つまでで、それぞれ別の UID と作業ディレクトリで動かすので、ほかの人のコードや出力は読めません。空きがなければ 20 秒まで待ち、それでも空かなければ「混み合っています」と返します
- 実行が終わるたびに、その UID のプロセスをすべて止め、作業ディレクトリを空にします。止められない・消せないときは sandbox を終了させ、Docker の再起動で作り直します

同時に実行できる数は `compose.yaml` の `tmpfs` の行の数で決まります（8 まで）。増やすときは `mem_limit` も合わせて見直してください。

コンテナはホストとカーネルを共有するので、カーネルの脆弱性を突かれた場合までは防げません。もう一段固くしたい場合は、サーバーに [gVisor](https://gvisor.dev/) を入れ、`SANDBOX_RUNTIME=runsc` を付けて起動すると、sandbox だけを gVisor で動かせます（gVisor での動作は未確認です。共有ボリュームにソケットを作るので、runsc の `--host-uds=create` が必要になるはずです）。

Docker Compose を使わずに `npm start` で動かす場合は、下の開発用と同じくポートで待ち受ける形になりますが、この形では実行中のコードが外部と通信できます。本番では Docker Compose で動かしてください。

開発サーバー（`npm run dev`）から使うときは、sandbox だけを起動し、`.env` に接続先を書きます。

```sh
docker compose -f sandbox/compose.dev.yaml up -d --build   # 127.0.0.1:8091 で待ち受ける
```

```sh
SANDBOX_URL=http://127.0.0.1:8091
```

### VS Code の拡張機能（STEP Learn for VSCode）

ファイル自動配布とコーディングエージェントのアイテムで使う VS Code の拡張機能は `vscode-extension/` にあります。本体とは別のパッケージで、型チェック・lint・ビルドも別に行います（本体の `npm run lint` は拡張機能を対象から外し、入れ子の設定も読みません。拡張機能の中に同じルールの `.oxlintrc.json` を置き、拡張機能の `npm run lint` で検査します。実行時の依存はなく、esbuild で 1 ファイルにまとめます）。拡張機能の使い方は [vscode-extension/README.md](vscode-extension/README.md)（Marketplace のページにもなる）にあります。

```sh
cd vscode-extension
npm install
npm run typecheck
npm run lint
npm run package     # step-learn-for-vscode-<バージョン>.vsix を作る（手元の VS Code に「VSIX からのインストール」で入れて試せる）
```

Marketplace への公開（無料）:

1. Microsoft アカウントで [Azure DevOps](https://dev.azure.com/) の組織を作り、「Personal access tokens」で Organization を「All accessible organizations」、Scopes を「Marketplace の Manage」にしたトークンを作る
2. [Marketplace の管理画面](https://marketplace.visualstudio.com/manage) で publisher `mint1535` を作る
3. `cd vscode-extension && npm ci && npx vsce login mint1535`（トークンを入力）→ `npm run publish`。`npm ci` を省くと、グローバルに入っている古い vsce が使われて `unknown option '--skip-license'` で失敗することがある。更新するときは `package.json` の `version` を上げてから `npm run publish`

拡張機能の ID は `mint1535.step-learn-for-vscode`（publisher と `package.json` の `name`）です。publisher か名前を変えるときは、`vscode-extension/package.json` と `src/lib/bundle.ts` の `VSCODE_EXTENSION_ID` をそろえてください。そろっていないと、「VS Code で開く」のリンクが拡張機能に届きません。

拡張機能のうち VS Code の API を使わない部分（`src/sync.ts` = ファイルを受け取って用意する、`src/history.ts` = 変更を集めて送る）は Node だけで動かせます。VS Code とつなぐのは `src/extension.ts`（リンクを受け取る）と `src/history-session.ts`（開いているフォルダーの保存を見張り、数秒待ってまとめて送る）です。

拡張機能が受け取るのは、リンクに書かれた https のサーバー（手元の開発では `http://localhost`）だけです。STEP Learn が「VS Code で開く」のリンクに入れるサーバーは `APP_ORIGIN`（なければ要求の URL）なので、リバースプロキシの配下では `APP_ORIGIN` を設定してください。

### 自動デプロイ（GitHub Actions のセルフホストランナー）

`master` への push で CI（`.github/workflows/ci.yml`）が成功すると、`.github/workflows/deploy.yml` が beta のサーバーのセルフホストランナー上で `docker compose build` → `docker compose up -d` を実行して入れ替えます。
CI はチェックだけを行い、デプロイはしません。Actions の画面から手動で再デプロイすることもできます（`master` のみ）。

| デプロイ | ランナーのラベル | Environment | Compose のプロジェクト（ボリューム） |
| --- | --- | --- | --- |
| beta | `beta` | `beta` | `step-learn-beta`（`step-learn-beta_data`） |

サーバー側の準備：

1. Docker（Compose v2.24 以上）を入れ、ラベル `self-hosted` / `linux` と、ラベル `beta` を付けたランナーを登録する（ランナーのユーザーが `docker` を実行できること）
2. GitHub の Environment `beta` に設定値を登録する。デプロイのたびに、ここから `.env` をランナーの一時ディレクトリに書き出してコンテナに渡し、終わったら消します
   - Secrets：`SESSION_SECRET` / `SMTP_PASS` / `MOODLE_EXCHANGE_TOKEN` / `MOODLE_BACKCHANNEL_SECRET` / `OPENROUTER_API_KEY` / `CLAUDE_API_KEY` / `MICROSOFT_CLIENT_SECRET`
   - Variables：`APP_ORIGIN` / `TRUST_PROXY` / `SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `MAIL_FROM` / `MOODLE_URL` / `AI_EMAIL_DOMAIN` / `MICROSOFT_CLIENT_ID` / `MICROSOFT_TENANT`
   - 使わない項目は登録しなくてかまいません。値に `'` と改行は使えません
   - Moodle モードで動かす場合は `MOODLE_URL` などを登録します
3. ホスト側のポートを変える場合は変数 `DEPLOY_HOST_PORT` を、公開するアドレスを変える場合は変数 `DEPLOY_HOST_BIND` を、Environment かリポジトリに設定する
   - AI エージェントが検索する STEP Docs の索引を置くディレクトリ（既定 `/srv/step-learn/ai-docs`）を変える場合は変数 `DEPLOY_AI_DOCS_DIR` を設定する（上の「STEP Docs を AI エージェントに取り込む」）
4. 必要に応じて、Environment に承認者などの保護ルールを設定する

```
src/renderer.tsx     HTML の外枠

src/lib/             設定・DB・認証・HTTP ヘルパー・Markdown・ストレージ・画像アップロード・コースの権限・AI（OpenRouter）・sandbox の呼び出し

src/components/      レイアウトと UI 部品
src/routes/<ルート>/ auth / account / admin / dashboard / courses / content / participants / screen / code / bundle / agent。
                     ルートごとに index.ts（ルーティング）・handlers.tsx（処理）・views.tsx（画面）・<ルート>.css に分ける
```

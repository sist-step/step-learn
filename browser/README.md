# browser

コーディング問題の Web の提出を、採点の前に headless Chromium で開き、判定の手がかりになる「実行の記録」を AI に渡すコンテナです（`server.mjs`）。書いてあっても効いていないコード（上書きされた CSS、押しても変わらないボタンなど）を、コードを読むだけの AI は見落としやすいためです。記録に何を入れるかは `server.mjs` にあります。

`docker compose up` でアプリと一緒に起動し、アプリは共有ボリュームのソケットで呼びます。`BROWSER_URL` が未設定のサーバーでは、Web の提出はコードだけで判定します。

## 隔離のしかた

- コンテナはネットワークにつながず、そのうえで Chromium はページの外からの読み込みをすべて止めます
- ルートファイルシステムは読み取り専用で、書き込めるのは `/tmp`（tmpfs）だけ。Chromium のプロファイルは実行ごとに作って消します
- ケーパビリティをすべて外し、アプリと同じグループの別の一般ユーザーで動かします。Chromium 自身の sandbox は、使うにはコンテナの権限を広げることになるので使っていません（`--no-sandbox`）
- 記録は、学生のコードから書き換えられないよう、ページとは別の world（isolated world）で取ります
- 上限の値（メモリ・同時に開く数など）は `compose.yaml` の `browser` サービスにあります

## 開発サーバーから使う

browser だけを起動し、`.env` に接続先を書きます。

```sh
docker compose -f browser/compose.dev.yaml up -d --build   # 127.0.0.1:8092 で待ち受ける
```

```sh
BROWSER_URL=http://127.0.0.1:8092
```
